# Security Policy

Report SDK vulnerabilities involving credentials, unsafe logging, dependencies, transport security or authorization-boundary mistakes through the private KritvaOS security reporting route. Do not disclose exploitable vulnerabilities in public issues. If the private route is unavailable, contact the project owner privately to establish a secure channel.

Never commit credentials, tokens, private keys, production data or personal data. Examples use fake values. Never log authorization headers, tokens or sensitive payloads. Client-side checks do not replace server authorization. Client timeout/cancellation does not prove remote rollback.
